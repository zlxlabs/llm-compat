# 业务背景

## 为什么要做这个包

### 现状

- 有 10+ 个 Python 项目需要调用 LLM API
- 所有项目通过 **New API**（OpenAI 兼容代理）统一接入
- New API 后端对接多家模型：DeepSeek V4、GPT-4o/4.1、Gemini、Doubao 等
- 经常在不同厂商模型间切换

### 痛点

1. **thinking/reasoning_effort 参数兼容性**
   - DeepSeek V4 有独有的 `thinking` 对象控制思考开关
   - 各家 `reasoning_effort` 值域不同
   - 切换模型时参数可能不兼容，但不会报错（静默降级或忽略）

2. **JSON 输出兼容性**
   - 不同模型返回 JSON 的格式不一致（code fence、bare list）
   - 每个项目都要写一遍清洗逻辑

3. **重复代码**
   - 重试、日志、超时等基础设施每个项目都在写
   - 修一个 bug 要改 10+ 个项目

4. **模型迁移成本高**
   - DeepSeek 旧模型 2026-07-24 停服，需要迁移所有项目
   - 如果兼容逻辑在包里统一处理，迁移只需更新包版本

### 为什么不用现有方案

- **LiteLLM** (45K stars): 太重（14.8MB），功能与 New API 重叠（都是网关/代理）
- **aisuite**: 设计为直连各家 API，而我们统一走 New API
- **OpenAI SDK**: 不处理跨 provider 差异

```
│           └──────────┬─────────┘                     │
│                      ▼                               │

```

## 设计约束

1. **零重依赖** — 核心只依赖 httpx，Pydantic 可选
2. **不做路由/鉴权** — New API 已经做了
3. **不做配置管理** — 各项目结构不同
4. **不做 Prompt 模板** — 各项目模板不同
5. **异步优先** — 主要消费者（Memos Auto）是 FastAPI 异步项目
6. **model 在调用时传入** — 同一个 client 可以调不同模型
7. **私有包** — GitHub 仓库，uv/pip 直接安装，不发 PyPI

## 成功标准

- Memos Auto 的 `llm_client.py` 从 538 行降到 ~200 行
- 新增 provider 只需在包里加一条 fnmatch 规则
- 切换模型只改配置，不改代码
- DeepSeek 迁移（2026-07-24 deadline）只需更新包版本 + 改配置
